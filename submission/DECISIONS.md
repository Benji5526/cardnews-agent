## 이미지 작업자 관련 결정

- **agy(Antigravity CLI) 보류.** 설치(`D:\Tools\agy\bin`)와 Google OAuth 로그인까지 됐고 텍스트 호출은 성공. 그러나 `agy -p`로 이미지 생성을 요청하면 서버 500 오류가 나거나, 하위 에이전트에 맡겼다는 응답만 남기고 파일 없이 끝났다.
- **Gemini 무료 한도 0.** 이 키로 쓸 수 있는 이미지 모델 6개가 모두 429(`free_tier_requests limit: 0`). 결제 연결 전까지 실제 이미지 생성은 미완료.
- **임시 처리:** 이미지가 막히면 "대체 배경으로 계속"으로 나머지 흐름을 진행하고, 해당 카드를 "대체 배경(실제 생성 미완료)"로 기록한다.

## 편집 규칙 (실습 "형식과 독자 선택" 반영)

1. 심층 조사 뒤 두 형식을 비교(적합 독자·장점·단점)하고 하나를 추천 이유와 함께 보여준다. 소식 수·근거 양을 고려한다.
2. 사용자가 미리 적은 편집 방향(독자·형식·표지)은 다시 묻지 않는다. 결과가 크게 달라질 때만 질문을 추가한다.
3. 제목의 "최신"은 조사 기준일과 원문 게시일로 뒷받침한다. 표지 카드에 `기준일 · 원문 게시일`을 표시한다.
4. 확인하지 않은 기능·효과는 표지(후킹) 문장에 넣지 않는다. 검수 단계에서도 점검한다.
5. 이미지는 `생성 이미지` / `대체 배경`으로 구분해 도구·약관 확인 필요·"실제 현장·제품 화면이 아님"을 `image_usage.json`에 기록하고, 생성 이미지 카드에는 "AI 생성 이미지"를 표시한다.
6. 카드 수는 5~8장 중 사용자가 선택 (기본 5).

## 미결·보완 필요

- (해결) CC0·퍼블릭 도메인 이미지 선택은 구현했다(아래 "CC0·퍼블릭 도메인 이미지 선택" 절). 라이선스 스톡(Pexels 등)은 구현하지 않았다.
- (해결) 첫 카드 후킹은 스토리보드와 별도 호출로 먼저 설계한다: 독자 관심 → 후보 2개(근거·과장 위험) → 선정 → 그 문구로 첫 카드 작성. 설계 내용은 기획 검토 화면에 표시.
- (해결) 작업 진행 내역에 엔진이 실제로 보낸 검색어, 읽은 원문 주소, 결과 수신, 후킹 설계를 단계별로 기록하고 화면에서 펼쳐 볼 수 있다. 닫아도 기록은 쌓인다. 생성 중인 텍스트의 실시간 요약은 아직 없음.
- Claude Agent SDK / OpenCode CLI 엔진은 연결하지 않음.

## 내 작업에 맞게 바꾼 흐름: 학습일지 → 블로그 포스트 + 요약 카드 (2026-10-23)

뉴스 카드뉴스 흐름의 틀(질문 대기·스토리보드 승인·검수·부분 수정·ZIP)은 그대로 두고, 네 가지를 바꾼다. 화면의 첫 선택지에서 "학습일지" 모드를 고른다.

| 구분 | 뉴스 카드뉴스(기존) | 학습일지(바꾼 흐름) |
|---|---|---|
| 입력 자료 | 주제 + 최근 N일 웹 검색 결과 | 오늘 공부한 메모 + 링크(선택) |
| AI 판단 | 소식 후보 수집, 두 형식 비교·추천 | 메모에서 개념 후보 추출, 링크·공식 문서와 대조해 메모의 오해·불확실한 부분 지적, 글 형식(TIL형·튜토리얼형·Q&A형·개념 설명형 중 두 가지) 비교·추천 |
| 사람 결정 | 소식 1~3개, 독자, 형식, 표지 문구 | 개념 1~3개, 독자 수준, 글 형식, 제목·표지 방향, 카드 3~8장 |
| 최종 산출물 | 카드 PNG + ZIP | Jekyll 마크다운 포스트(`post.md`, front matter 포함) + 요약 카드 PNG + 출처·이미지 사용 기록 ZIP |

- 조사 기간(최근 N일) 개념은 학습일지에 맞지 않아 기준일(오늘)만 표시한다. 메모만 있고 원문 링크가 없는 개념은 출처가 "내 메모"이고, 카드에는 링크 출처를 넣지 않는다.
- 포스트는 확인된 사실과 메모, 카드 내용에서만 쓰고, 메모에서 원문과 달랐던 부분은 "바로잡은 점" 섹션에 따로 적는다.
- 카드 수정 후에는 포스트가 카드와 어긋날 수 있어 "포스트 다시 쓰기" 버튼을 둔다.

## 엔진 연결·질문 대기·이어가기 방식 (2026-10-23)

- **엔진:** Claude CLI(`claude -p`)를 서버에서 실행한다. 엔진 호출은 `src/engines.ts`에 분리돼 있고, 단계별 프롬프트는 `src/pipeline.ts`에 있다. 브라우저가 직접 명령을 실행하지 않는다.
- **이어가기: `--resume`(세션 ID)을 쓰지 않는다.** 대신 앱이 저장한 맥락(선택한 소식·근거·사용자 답변·현재 원고)을 매 호출의 프롬프트로 다시 전달한다.
  - 이유: 서버를 재시작해도, 엔진 프로세스가 사라져도 `job.json`만으로 이어갈 수 있다. 프로젝트마다 호출이 독립이라 두 프로젝트의 세션이 섞일 수 없고, 엔진을 바꿔도 같은 맥락을 줄 수 있다.
  - 대가: 호출마다 맥락을 다시 보내 토큰이 더 들고, 엔진이 이전 대화를 기억하지 못한다.
- **질문 전달:** `need_input` 같은 엔진 출력 규약을 쓰지 않고, 질문 자체를 앱의 단계로 둔다(심층 조사가 질문을 만들고 `editorial` 단계에서 멈춘다). 엔진이 대화 도중 멈춰 기다리지 않으므로 서버 재시작 시 사라지는 대기 콜백이 없다.
- **상태:** `job.status`는 `running` / `waiting_for_user` / `failed` / `done` 중 하나다(`busy`·`error`·`stage`에서 계산). 질문이 만들어지면 `qVersion`이 1 오른다.
- **중복·지난 답변 방어:** 답변 제출은 질문 버전(`version`)을 함께 보내야 한다. 작업이 이미 진행 중이거나(같은 답 중복), 단계가 지났거나, 버전이 다르면 409를 돌려주고 현재 작업·답변을 바꾸지 않는다. 화면은 제출 버튼을 즉시 비활성화하고, 거절되면 안내 후 현재 상태로 다시 그린다.

## 이미지 작업자: agy 연결 (2026-10-23)

이전 결정("agy 보류")을 바꿨다. 5절 안내가 agy의 이미지 도구(`generate_image`)와 헤드리스 권한 거부 대응을 직접 다루고, 빈 작업 폴더에서 `agy -p ... --dangerously-skip-permissions`로 실제 PNG가 만들어지는 것을 확인했기 때문이다(896×1200, 글자 없음, 하단 여백).

- **구조:** `src/imageWorker.ts`가 작업자(`agy` / `gemini`)를 고른다. `IMAGE_WORKER=agy|gemini|auto`(기본 auto: agy가 설치돼 있고 도구 자동 승인이 켜져 있으면 agy, 아니면 Gemini).
- **성공 판정은 파일로:** 응답 문장·종료 코드가 아니라 작업 폴더에 저장된 이미지의 시그니처(PNG/JPEG/WEBP)와 크기(20KB 이상)를 확인하고, 앱 폴더에 저장한 뒤 다시 열어 확인한 경우에만 `ok`로 기록한다. 파일이 없으면 실패로 기록하고 해당 카드에 오류와 재시도를 보여 준다(다른 카드 결과 유지).
- **권한:** `--mode accept-edits`와 `--mode auto`는 둘 다 `RunCommand`가 거부돼 파일이 생기지 않았다. 허용 규칙 문법은 공식 자료에서 찾지 못해 사용자 전역 설정을 추측으로 바꾸지 않았다. 그래서 `--dangerously-skip-permissions`를 쓰되 다음으로 위험을 줄인다.
  - `AGY_ALLOW_ALL_TOOLS=1`을 **명시적으로 켠 경우에만** 쓴다(기본 꺼짐). 꺼져 있으면 대체 배경으로 진행하고 사유를 기록한다.
  - 요청마다 새 **빈 작업 폴더**에서 실행하고, 끝나면 그 폴더만 지운다.
  - 장면 설명은 한 줄·700자·주소와 꺾쇠 제거로 정제하고 `<scene>` 안의 "데이터"로만 쓰라고 지시한다(웹 자료에서 온 문장이 지시처럼 작동하지 않게).
  - 한계: 이 옵션은 그 실행의 모든 도구 요청을 자동 승인한다. 정제와 빈 폴더가 완전한 격리는 아니다. 웹 서비스로 공개할 때는 필요한 도구만 허용하는 규칙으로 바꿔야 한다.
- **메타데이터:** `image_usage.json`에 작업자·도구·크기·"설명용 생성 이미지, 실제 제품 화면·발표 장면 아님"을 기록하고, 카드에 "AI 생성 이미지"를 표시한다.

## 확장 과제에서 추가한 결정 (2026-10-23)

- **자료가 부족하면 지어내지 않고 부족한 점을 표시한다.** 학습일지 모드는 `gaps`를 화면에 보여 주고, 후보를 만들 수 없으면 오류 상태로 멈춘다. 이때 막다른 길이 되지 않도록 같은 작업에서 메모를 보완해 다시 정리하는 경로(`POST /jobs/:id/notes`)를 둔다.
- **확인하지 못한 날짜는 발표일로 쓰지 않는다.** 카드·출처 파일에는 실제 발표·변경일이 확인된 경우만 "발표"로 쓰고, 아니면 "게시 … · 발표일 미확인"으로 표시한다. 이전 방식으로 저장된 작업은 불러올 때 보정한다.
- **카드를 수정하면 사실·출처 검수를 자동으로 다시 실행한다.** 검수 결과가 없는 카드는 점검에서 "통과"가 아니라 "미확인"이다. 자동 검수는 매번 같은 결과를 주지 않으므로 지적은 사람이 원문과 대조하는 단서로만 쓴다.
- **이미지 사용량 한도(agy `RESOURCE_EXHAUSTED`)는 첫 실패에서 멈추고** 응답에 적힌 재설정 시간을 안내한다. 한도가 풀릴 때까지는 "대체 배경으로 계속"을 선택할 수 있고, 실제 생성은 미완료로 기록된다.
- **"내보낸 파일 점검"을 둔다.** 서버가 확인할 수 없는 항목(모바일 가독성, 원문 대조 등)은 통과로 처리하지 않고 사람이 확인할 항목으로 안내한다.

## CC0·퍼블릭 도메인 이미지 선택 (2026-10-23)

생성 이미지가 막힐 때(agy·Gemini 한도)의 대안이자, 안내문의 "이미지는 CC0·퍼블릭 도메인 / 라이선스 허용 스톡 / 생성 이미지로 구분해 출처와 사용 조건을 기록" 요구를 채우기 위해 추가했다. 이번에는 **CC0·퍼블릭 도메인**만 구현했고 라이선스 스톡(Pexels 등)은 구현하지 않았다.

- **공급처: Wikimedia Commons.** Openverse도 시험했지만 응답이 느리고(cc0 질의가 40초 시간 초과) 검색 결과 관련도가 낮았다("server rack" 검색에 무관한 사진). Commons는 1.5초 안팎으로 응답하고 관련 사진이 나왔으며, 라이선스 필드(`LicenseShortName`)로 CC0·퍼블릭 도메인만 걸러낼 수 있다. API 키가 필요 없다.
- **사람이 고른다.** 검색어는 영어로 사람이 고쳐 쓰고, 후보(미리보기·라이선스·작가·크기·파일 페이지 링크)를 보고 한 장을 직접 고른다. 앱이 자동으로 고르지 않는다. 카드 하나만 바뀌고 다른 카드는 유지된다.
- **서버가 다시 확인한다.** 사용자가 고른 이미지는 번호만 받고, 서버가 Commons에서 라이선스·형식을 다시 조회한 뒤 `upload.wikimedia.org`·`thumb.wikimedia.org`(https만, 리다이렉트 금지, 15MB 이하)에서만 내려받고, 파일 시그니처를 확인한다. 클라이언트가 보낸 주소는 쓰지 않는다.
- **기록:** `image_usage.json`에 작가·라이선스·파일 페이지·"실제 발표 현장·제품 화면 아님"을, `sources.md`에 "이미지 출처와 사용 조건"을 남기고, 카드에 "이미지: CC0 · Wikimedia Commons"를 표시한다.
- **한계:** 라이선스 표시는 Commons 메타데이터 기준이다. 사진 속 인물·상표·간판의 권리는 별도일 수 있어 게시 전에 파일 페이지를 확인하라고 기록에 적는다. 크기 기준(짧은 변 700px 이상, 긴 변 1200px 이상)에 못 미치는 파일은 후보에서 뺀다.
- **승인 해제:** 최종 승인 뒤에도 고칠 수 있도록 "승인 해제하고 수정하기"(`POST /jobs/:id/reopen`)를 추가했다. 카드·이미지는 유지되고 최종 승인만 풀린다.

## 보안 점검과 조치 (2026-10-23)

구현자와 별개의 보안 검토 에이전트가 코드를 읽고 지적한 것을, 제가 코드에서 직접 확인한 뒤 고쳤다(높음 3·중간 4·낮음 5 중 확인된 것).

| 지적 | 조치 |
|---|---|
| 저장형 XSS: 모델이 만든 질문 id가 이스케이프 없이 HTML 속성에 들어감 | 서버가 id를 `^[a-z][a-z0-9_]{0,31}$`로 검증하고 선택지는 문자열만 허용. 화면은 `esc()`·`CSS.escape()` 사용. CSP 헤더(`script-src 'self'`) 추가 |
| DNS 리바인딩·교차 사이트 요청: Host·Origin 검사 없음 | 로컬 Host만 허용(421), 다른 Origin의 상태 변경 요청 403, `application/json`이 아닌 POST 415 |
| agy 프롬프트 주입(자동 승인 모드) | 장면 설명을 영문자·숫자·기본 문장부호만 남기고, 명령·유출을 시키는 문장은 버림. 사용자의 자유 문장은 agy에 직접 보내지 않고 도구 없는 Claude 호출로 영어 장면 설명만 새로 쓰게 함 |
| `javascript:` 주소가 링크로 렌더링됨 | 링크는 http(s)만, 서버도 근거 주소를 http(s)만 저장 |
| `job.json` 저장 실패·손상 파일이 서버를 죽일 수 있음 | rename 재시도 후 직접 쓰기, 실패해도 예외를 던지지 않고 기록만. 손상된 파일은 건너뜀 |
| 입력 크기 제한 없음 | 요청 본문 64KB(카드 PNG만 12MB), 주제 200자, 수정 요청·피드백 2000자, 답변 500자, 답변 키 형식 제한 |
| 진행 중에 상태를 바꾸면 오래된 상태가 덮어씀 | 상태를 바꾸는 요청은 진행 중이면 변경 전에 409 |
| 그 밖 | 오류 응답에서 내부 경로 노출 차단, 포스트의 `<script>`·`on*=`·`javascript:` 제거, 이미지 다운로드는 본문 크기 상한 적용, 이미지 테스트 동시 실행 제한 |

**고치지 않은 것(위험을 알고 남김)**
- `AGY_ALLOW_ALL_TOOLS=1`은 위 정제를 거쳐도 완전한 방어가 아니다. 영어 문장으로 다시 쓰인 지시를 모두 걸러낼 수 없고, 빈 작업 폴더는 격리가 아니다. 별도 계정·샌드박스가 없으면 켜지 않는 것을 권한다.
- 동시 실행 자식 프로세스 수 제한, 출력 버퍼 상한, Windows에서 자식의 자식까지 종료하는 처리는 하지 않았다(한 사용자가 로컬에서 쓰는 앱이라 우선순위를 낮춤).
- 로그인이 없다. 이번 방어는 다른 웹페이지의 접근을 막는 것이며 같은 PC의 다른 사용자는 막지 못한다.

## 호주 데일리 뉴스 모드 (2026-10-26)

"매일 호주 빅 뉴스를 한국어로 번역해 카드로 만들기"를 위해 추가했다. 사용자가 정한 방향: 자동 제작 후 사람이 승인 / 오늘의 호주 뉴스 한 편(5~6장) / 단색 배경.

- **자동 제작, 승인은 사람:** `POST /jobs`에 `mode: "au"`를 주면 서버가 사람의 선택·질문 없이 후보 조사 → 큰 뉴스 3~4건 선택 → 심층 검증 → 스토리보드 → 단색 배경 → 검수까지 이어서 실행한다. 스토리보드 승인 단계는 건너뛰고, **최종 검수·승인은 사람이 한다**. 중간에 실패하면 멈추고 화면에서 그 단계부터 이어갈 수 있다. 자동 실행 중에는 `autoRunning`으로 화면 조작과 중복 실행을 막는다.
- **"큰 뉴스" 선정:** 모델이 여러 호주 매체(ABC, SBS, Guardian Australia, SMH 등)에서 중요도 순으로 정렬해 주면, 원문을 실제로 연 후보를 우선해 위에서 4건을 고른다. 선정 기준(전국적 영향, 정책·경제·재난, 여러 매체의 동시 보도, 한국과의 관련)은 프롬프트 지침이며 실행마다 순위가 달라질 수 있다.
- **시드니 기준 하루:** 기준 시각을 시드니·한국 시각으로 함께 표시하고, 기간은 시드니 날짜로 어제~오늘이다. 서머타임은 `Intl`로 오프셋을 계산한다. 실제 발표일이 기간보다 이전이면 후보에서 뺀다(예: 10월 19일 사건).
- **번역 방침:** 기사 전문 번역이 아니라 **요약 번역 + 원문 링크 표기**다. 인명·지명·기관은 한국어 표기에 영문을 병기하고, 금액은 AUD로 표기한다. 카드에 "한국어 번역·요약 · 원문은 출처 참조"를 표시한다.
- **이미지:** 기사 사진은 저작권 때문에 쓰지 않고, 이미지 생성도 하지 않는다(매일 수십 장이면 한도가 빨리 소진됨). 단색 그라디언트 배경을 쓰고, 내보낸 파일 점검은 이를 의도된 것으로 통과 처리한다.
- **자동 품질 보강(첫 실행에서 발견한 문제):** 첫 실행에서 모델이 선택한 뉴스 1건(아동 폭행)을 카드에서 조용히 빼고 다른 뉴스를 두 장으로 쪼갰으며 표지는 "네 가지"라고 적었다. 그래서 (1) 스토리보드 지침에 "빠뜨리지·쪼개지 말 것, 건수 일치, 정리 카드에 해석 금지, '오늘'은 기준일 하루만"을 넣고 (2) 뉴스마다 카드가 있는지 코드로 확인해 빠졌으면 한 번 다시 쓰게 하고 (3) 검수가 지적한 카드를 사람이 보기 전에 1회 자동 수정한다.
- **매일 실행:** `npm run daily`(서버를 켜고 작업을 만들어 주소를 알려 줌). 하루 한 번 실행되게 하는 Windows 작업 스케줄러 등록은 사용자의 시스템 설정을 바꾸는 일이라 이 저장소가 대신 하지 않고, README에 명령 예시만 둔다. PC가 켜져 있어야 한다.
- **한계:** 번역 정확도·인명 표기·"큰 뉴스" 판단은 앱이 보증하지 않는다. 호주 매체의 이용 조건은 공개 게시 전에 직접 확인해야 한다. 모델의 중요도 판단은 실행마다 달라질 수 있다.
